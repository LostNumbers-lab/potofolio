# 챗봇 관리자

접속 주소: `https://lostnumbers-lab.github.io/potofolio/chatbot/admin/`

## 운영 흐름

1. 발급된 관리자 아이디와 비밀번호로 로그인합니다. 자격 증명은 공개 소스에 들어 있지 않습니다.
2. **대화 데이터**에서 질문·답변·키워드·버튼·이동 단계를 수정합니다. 질문 추가/삭제, 검색, 전체 JSON 편집 및 다운로드를 지원합니다.
3. **초안 저장**은 서버 초안만 변경합니다. 공개된 챗봇에는 반영되지 않습니다.
4. **미리보기**에서 저장한 초안의 동작을 확인합니다. 미리보기 문의 폼은 전송이 차단됩니다.
5. **최종 게시** → 버전 이름 입력 → **이 내용으로 최종 게시**를 눌러야 공개본이 전환됩니다.
6. **게시 버전**에서는 번호·이름·게시 시각·작성자·현재 게시 여부를 확인합니다. **초안으로 불러오기**는 이전 내용을 초안으로 복원할 뿐 공개본을 바꾸지 않습니다. 복원 후에도 미리보기와 최종 게시가 필요합니다.
7. **문의함**은 기존 `public.consultations`에서 category=`제작 문의`인 데이터만 조회합니다. 문의 상태와 관리자 답변 메모를 저장할 수 있습니다. 자동 이메일 발송 기능은 없습니다.
8. **계정 설정**에서 관리자 비밀번호를 변경할 수 있습니다. 변경 시 기존 세션은 모두 종료됩니다.

수정은 우선 브라우저 편집기에 보관되고 초안 저장 시 Supabase에 저장됩니다. 마지막으로 저장하지 않은 수정은 다른 페이지로 이동하거나 로그아웃하면 잃을 수 있어 안내합니다. 다른 관리자 탭에서 초안을 변경한 경우 덮어쓰기를 막고 최신 초안 불러오기를 요청합니다.

## 데이터와 공개 반영

초안과 게시 버전은 Supabase의 JSONB로 관리합니다. 게시 시 JSON 스냅샷을 새 버전으로 저장하고 현재 게시 포인터를 원자적으로 전환합니다. 이전 버전은 보존하며 이력 삭제 기능은 두지 않았습니다.

공개 챗봇은 서버의 현재 게시 JSON만 읽습니다. 최종 게시 후 새로고침하거나 홈페이지 챗봇을 닫았다 다시 열면 최신 게시본을 불러옵니다. 운영 내용 변경마다 GitHub 소스 커밋·재배포를 할 필요는 없습니다. 저장소의 `chatbot/data/chatbot.json`은 초기 기본본/서버 장애 시 안내용 백업이며, 관리자 게시 시 GitHub 파일 자체를 덮어쓰지는 않습니다. 필요하면 JSON 다운로드를 통해 수동 백업할 수 있습니다.

## 인증과 접근 제어

- 로그인은 `chatbot-console` Edge Function에서 서버 검증합니다. 비밀번호는 DB에 bcrypt 해시로 저장됩니다.
- 계정은 현재 관리자 1개이며 공개 가입/추가 관리자 생성 API는 없습니다.
- 로그인 실패 10회 시 15분 잠금, 세션 유효기간 8시간, 로그아웃 시 서버 토큰 폐기를 적용했습니다.
- 세션 원문은 해당 브라우저 탭의 sessionStorage에만 저장합니다. DB에는 토큰 SHA-256 해시만 저장합니다. 관리자 데이터는 브라우저 영구 저장소에 저장하지 않습니다.
- 관리자 테이블은 RLS와 권한 회수로 anon/authenticated/PUBLIC의 직접 접근을 차단합니다. 공개 publishable 키로 문의·초안·이력·계정 데이터를 조회할 수 없습니다.
- 관리 RPC는 SECURITY INVOKER이며 service_role만 실행할 수 있습니다. Edge Function이 세션을 검사하고 RPC도 다시 검사합니다. 서버용 키는 Supabase 런타임 환경에서만 읽으며 브라우저·GitHub에는 포함하지 않습니다.
- Edge Function의 verify_jwt=false는 자체 관리자 세션 검증과 공개 게시본 GET을 위한 설정입니다. 관리자 작업을 무인증으로 허용한다는 의미가 아닙니다.
- 기존 RLS 자동 설정 이벤트 트리거 함수는 브라우저에서 호출할 기능이 아니므로 PUBLIC/anon/authenticated의 EXECUTE 권한을 회수했습니다.

Security Advisor 점검 후 경고/오류는 없으며, 관리자 테이블 4개에는 의도적으로 클라이언트용 RLS 정책을 만들지 않아 기본 거부 상태라는 정보 알림만 있습니다. [RLS 기본 거부 안내](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy)를 참고하세요.

새 비밀번호는 8자 이상으로 설정할 수 있습니다. 초기 자격 증명은 서버에만 등록되어 있으므로 공개 문서나 예제 코드에 기재하지 않습니다.

## 서버 구성

- `supabase/chatbot-console.sql`: 실제 적용한 테이블·함수·권한 구성 기록. 빈 개발 DB용이며 기존 운영 DB에 반복 실행하지 않습니다.
- `supabase/functions/chatbot-console/index.js`: 관리자 인증·초안·게시·버전·문의 API.
- `supabase/functions/chatbot-console/engine.js`: 프런트와 동일한 데이터 검증 모듈. 변경 시 양쪽을 일치시키며 자동 테스트가 이를 확인합니다.
- `chatbot/data/console-config.json`: 공개 API 주소와 브라우저용 키.

## 검증

- `node --test tests/*.test.mjs`: 분기, 데이터 제한, 서버/클라이언트 검증 일치, 문의 매핑 등을 확인합니다.
- `node scripts/verify-console-public.mjs`: 실제 서버의 공개 게시본, 미인증 관리 API 차단, 위조 토큰 차단, 관리자 테이블 직접 접근 차단을 읽기 전용으로 확인합니다.
- `tests/console-database.sql`: rate limit, 세션, 충돌 방지, 초안/복원 격리, 로그아웃, 비밀번호 변경 시 세션 폐기를 트랜잭션 안에서 검증하고 ROLLBACK합니다. 실제 관리자 비밀번호는 테스트 코드에 포함되지 않습니다.

2026-10-26 브라우저로 로그인·초안 저장·미리보기·버전 복원·최종 게시·문의 조회/메모 저장을 검증했습니다. 검증 문구는 제거했으며 v2 `관리자 게시 기능 연결 확인 · 기존 답변 유지`가 현재 게시본입니다. v1 최초 게시본도 이력에 남아 있습니다.
